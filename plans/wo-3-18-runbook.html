A scope justification you can paste and edit

Planbook is a local-first gradebook for classroom teachers. Everything it stores lives in the browser's own storage on the teacher's device; there is no backend and no account.

drive.file is used for exactly one feature: an optional sync that carries a single JSON document — the teacher's year file — between their laptop and their tablet. The app creates that file and reads back only that file, matched by an appProperties id it wrote itself. It never lists, opens or modifies anything else in the user's Drive, and it requests no other Google API or scope.

A narrower scope would not work, because the app must create and then update its own file across sessions and devices. A broader scope is not needed and is deliberately refused.

Five ways this goes wrong

Adding a scope resets the clock

A spreadsheets scope to read Roll Call!'s sheets, or a mail scope instead of mailto:, re-opens verification and puts the warning back in front of a teacher. The architecture in CLAUDE.md exists to keep that list at one.

The service worker hid the policy from you and not from them

sw.js used to answer every navigation out of the cache with the app shell, so any device with the worker installed rendered the gradebook at the policy URL — invisible from exactly where you would test it, since a reviewer fetches cold and sees the policy. Fixed in the tree, CACHE bumped to v92, and proved by mutation in a real worker — but unverified on hardware, which takes a deploy and a force-quit.

The wrong Google account

Domain verification is per-account. Personal Gmail, not the school Workspace one — which is also the right long-term call, since an employer's account disappears with the job and takes the Cloud project with it.

A policy that oversells the architecture

No encryption claim — IndexedDB is not encrypted and neither is the JSON backup. No retention promise the app cannot keep. No "we do not sell your data," which is a sentence about a vendor that receives data. The position here is genuinely strong, and every unverifiable sentence beside it invites doubt about the true ones.

Treating Testing mode as a destination

It works for you and up to a hundred test users, and it is exactly the thing this work order replaces. Every one of those users is a name you typed into a console by hand.
