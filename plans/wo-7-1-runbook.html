What this actually is, in small words

It is a hotel keycard, not a password

The app walks up to Google's front desk and says I am Planbook, and I would like to open one drawer. You show Google who you are — the app never sees your password, ever — and Google hands back a plastic card. The card opens only the files this app itself made, nothing else in your Drive. It stops working after about an hour, and there is no way to renew it while you are asleep. If you want a new one, you have to be standing at the desk.

That last part is not a limitation to work around. It is why sync can only ever happen while the app is open in front of you, and why nothing in this project may be built as if it syncs in the background.

That exact address. Not 127.0.0.1, not the LAN address, not port 8080. Google matches scheme, host and port as one string, so a different spelling of the same machine is a different origin and it will refuse. An origin not allowed error here almost always means you are at the wrong URL, not that the code is broken.

Traps — every one of these has bitten this project or its predecessor

The origin is a string, not a machine

https://localhost:8443 and https://127.0.0.1:8443 are the same computer and two different origins. So is the LAN address. Google compares the text. Test at the exact URL you registered, every time.

Never a second scope

Not spreadsheets — it reads every spreadsheet you own. Not a mail scope — outreach goes out through mailto: and needs no permission at all. Those two additions are what put an unverified-app warning in front of a stranger forever.

Never a backend, never Apps Script

Both look tempting the moment sync gets awkward. A backend makes us a FERPA data processor with breach liability; Apps Script makes every teacher their own unverified developer. Neither is a casual decision to revisit.

Never assume background sync

There is no refresh token in a browser. Sync is a foreground act, while the app is open and you are signed in. A feature that assumes otherwise cannot be built here, however reasonable it sounds in a sentence.

Google's script is the first remote file in this app

It cannot be precached and must not go in SHELL. The app has to open, work and stay useful when that script never loads — offline, or behind a Workspace admin who blocks third-party apps.

Sync is still not a backup

Drive holds one live copy that the next sync will happily overwrite. The downloadable JSON stays mandatory. Nothing in this work order or the next one relaxes that.

Bump CACHE in sw.js

Any change to a file in SHELL needs the bump in the same commit. Without it, no device sees the change — and you will spend an afternoon debugging a build that was never delivered.

Do not press Publish app

Testing mode is doing exactly what you need: real drive.file tokens for one test user. Publishing starts a verification you cannot complete until the policy is live, the video is filmed and WO-3.18 is submitted.
