Suite Style Guide

Colors and design language, in one portable file

Presentation mode is on. Sensitive fields are hidden. This strip is the violet "special state" accent doing its one job — a mode you are in, not a warning.
The caution banner. Amber, hairlined, with the action solid rather than outlined. Use it for a standing condition the user should act on — offline, stale data, no backup yet — never for an error that just happened.

How to carry this into another project

One file, no dependencies, no build step, no fonts to load. It works from file://.

Copy this file into the new repo's design/ folder, change the app name in the header and the favicon emoji, and paste §11's base layer into the new app's stylesheet before any screen styles. Click any swatch to copy its hex.

Three rules make the lift safe, and all three read like mistakes: colors are written out literally, never as custom properties — hoisting the navy into --navy means the whole suite has to migrate at once or the apps stop being copy-paste compatible; there is no dark mode anywhere — the navy chrome IS the light theme, not a dark skin of it, so don't write dark variants for new elements; and the responsive blocks come last, in the order coarse → 1024 → 640, because the touch pass has to be able to override the base rules it re-states.

Class names are the other half of portability. Keep them. Shared names are what let a fix travel between sibling apps — the app name, the favicon emoji, the localStorage prefix and the header subtitle are the only things that change.

1 · Palette

Click a swatch to copy its hex. Two families: dark chrome and light page.

Chrome — the dark surfaces

On-dark text: #fff; secondary rgba(255,255,255,0.5–0.6); hints rgba(255,255,255,0.45). On-dark controls: background rgba(255,255,255,0.08), border 1.5px solid rgba(255,255,255,0.15–0.25), hover background rgba(255,255,255,0.16–0.18). White alpha rather than a second set of hexes, so one control works over any point of the gradient.

Page — the light surfaces

Four greys for text and four for lines is not indecision — it is the whole hierarchy. A panel with one grey in it reads flat, and a panel with six reads noisy. Pick the role, then take its value.

The one accent with no border tint — a 9px badge sitting inside a row has no room for one, so it takes the neutral #e0e4ea if it needs an edge at all.

The rule that makes all of this hold together: interactive chips and buttons are wash background + strong-color text, optionally with a 1.5px tinted border. A solid strong-color fill is reserved for the active or selected state and for one primary action per surface. Break that and the screen loses its ability to say which thing is chosen — everything shouts at the same volume.

Reach for a wash before you reach for a new hue. Four semantic colors, each with three values, cover more ground than eight hues do, and a fifth hue is almost always a sign that two meanings should have been one.

Derived from the id, never stored — so a person keeps the same color on every screen with nothing to migrate and nothing to keep in sync. All ten carry white text at 800 weight; the two lightest (#d4ac0d, #0097a7) are the reason initials are bold rather than 600.

These are identity, not status. Four of them are also semantic accents, which is fine on a 32px circle of initials and is not fine anywhere a color carries meaning — never let an avatar hue sit next to a status chip of the same hue and imply a relationship.

4 · Typography

One stack, small sizes, heavy weights. Headings are small and bold, not large.

The stack

'Segoe UI', system-ui, sans-serif everywhere, and every <button> / <input> gets font-family: inherit — form controls do not inherit it on their own, and one missed input is a visibly foreign widget. Anything meant to be pasted into an email uses Arial, Helvetica, sans-serif instead, because that is what survives the trip. No web font is loaded, ever — it is a network dependency on a first paint that has to work offline.

Weights carry the hierarchy, not sizes. 600 for names and labels, 700 for buttons and titles, 800 for statistics and big numbers. The whole UI lives between 9px and 16px; if something needs to be louder, make it heavier or give it a wash, don't make it bigger.

Every timer, percentage and counter takes font-variant-numeric: tabular-nums. Without it a ticking clock jitters its own width, and a column of percentages will not line up.

6 · Components

Live specimens. Every one of these is real markup with the real classes — copy from the page source.

🔍
✓ Saved
Buttons

The last three take their accent on hover only. In a row of five buttons the destructive one must never look like the other four — but colouring all five five ways is a row nobody can scan, so the resting state stays one visual family and the color arrives when the pointer does. Disabled is opacity: 0.45 plus cursor: not-allowed; it is never hidden, because a control that vanishes is a control the user hunts for.

Toggles and filter pills

Both carry aria-pressed, and a pill row is wrapped in role="group" with a label. Note the two grammars: a toggle's on-state is a wash (it is one of several independent switches), a pill's is a solid fill (exactly one of the row is chosen).

Save indicator — all states at once
⏳ Saving… ✓ Saved ✕ Save failed ↻ Syncing… ↻ Retrying…

Wash backgrounds with strong text, at 11px/600 in a 10px-radius pill. A sixth state, queued, exists only in apps with a remote write queue — in a local-first app a write that has not landed has failed, not queued, and offering the softer word would be a lie the user acts on.

On-dark controls

Shown against the gradient because that is the surface they were designed for — on white they are invisible. The two active states invert differently and on purpose: a primary tab goes to near-black #1a1a2e, a context tab goes to white with #1a3c5e text. Two levels of navigation cannot both be the loudest thing in the bar.

Modal

Two openers, so focus-return is testable: Escape or a backdrop click has to put focus back on whichever button opened it, not on the first one on the page. The z-index ladder is fixed across the suite — content banners 90 · loading 999 · modals 1000 · setup screens 1001 · hero 1100 — so that a fix to one app's stacking travels to the others.

Icons — inline SVG, no icon font, no image files

Feather-style, always viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2.2" with round caps and joins. 16×16 on desktop, 18×18 on touch. stroke="currentColor" is what lets one icon sit in a white header button and a red delete button without a second copy.

Empty state
Nothing to show yet. This is what a panel looks like with no rows in it.

48px of vertical padding, centred, #a0aab8 at 13px. Every list gets one — a panel that collapses to nothing when empty reads as a bug.

8 · States

Five states, and the focus ring is the one that is not negotiable.

StateTreatment
HoverSolid buttons darken one step. On-dark controls brighten their white alpha. Outline buttons take the accent on border and text.
Active / selectedSolid accent fill with white text. On the dark header this inverts instead — white background, navy text.
Disabledopacity: 0.35–0.5, cursor: not-allowed, washed colors. Present, not hidden.
Focus:focus-visible { outline: 2px solid #5b6fcc; outline-offset: 2px; }
LoadingSkeleton shimmer for content, a spinner only for a blocking wait.

Never remove the focus ring, and never style bare :focus. Use :focus-visible so a mouse click doesn't leave a ring behind but a Tab key does. If a starter template you are lifting from suppresses an outline — some do, on search inputs — drop that rule rather than lift it: a box that draws no focus affordance of its own leaves a keyboard user with no idea where they are.

9 · Responsive & touch

Four breakpoints, declared in this order. The order is load-bearing.

QueryWhat it does
(pointer: coarse)The touch pass. Every interactive control gets min-height: 44px, icon buttons 44×44, fonts bump 1–2px, hover-only affordances become always visible. Every new control must appear in this block.
(max-width: 1024px)Tablet: search stretches, the centred pill row un-centres and wraps, grids drop a column.
(max-width: 640px)Phone: page padding 10px, modals width: 95vw, two-column grids, bars wrap.
(orientation: portrait) and (max-width: 1024px)Portrait-tablet grid tweak.

The touch pass comes first so the width queries can override it, and it is pointer: coarse rather than a width, because a 1024px iPad and a 1024px laptop need different targets at the same size.

iOS specifics, all of them scars: a viewport meta with maximum-scale=1.0; apple-mobile-web-app-capable; env(safe-area-inset-*) on every full-bleed row; overscroll-behavior-y: contain to kill rubber-banding; -webkit-overflow-scrolling: touch on scrollers; and touch-action: manipulation; user-select: none on every tappable class, in one grouped selector at the top of the sheet, which is what removes the 300ms tap delay and stops a long-press from selecting a button's label. Inputs go to 16px on touch — under 16px, iOS zooms the whole page on focus and does not zoom back.

10 · Accessibility

The parts that are easy to skip and expensive to retrofit.

Every icon-only button carries both aria-label and title — the label for a screen reader, the tooltip for a sighted user who cannot place the glyph. Toggles carry aria-pressed; a filter row is role="group" with a label; visually hidden text uses a .sr-only utility rather than display: none, which removes it from the accessibility tree as well.

Emoji used as decoration get aria-hidden="true". Otherwise a screen reader announces "memo" before your app's name, every single time.

Live announcements go through one announce() helper into a single aria-live region, never through the visual indicator. A save failure shows as a red chip and is announced, because the chip is not something a screen-reader user has any reason to be looking at. One region, one helper — two live regions race each other and the second message wins.

Color is never the only signal. Every status chip in this guide carries a glyph or a word as well as a wash: ⏳ ✓ ✕ ↻. Around 8% of men have some form of color vision deficiency, and in a classroom app the person reading the screen is often doing it over someone's shoulder at an angle, on a projector, in daylight.

11 · The base layer

Paste this into a new app's stylesheet first, before any screen styles.

/* Reset — all three properties, on everything. */
* { box-sizing: border-box; margin: 0; padding: 0; }

body {
  font-family: 'Segoe UI', system-ui, sans-serif;
  background: #f0f2f5;
  color: #1a1a2e;
  font-size: 14px;
  min-height: 100vh;
  overscroll-behavior-y: contain;
  padding-bottom: env(safe-area-inset-bottom, 0px);
}

/* Form controls do not inherit the font. One missed input is a foreign widget. */
button, input, select, textarea { font-family: inherit; }

/* Never remove this. Never style bare :focus. */
:focus-visible { outline: 2px solid #5b6fcc; outline-offset: 2px; }

/* The show/hide mechanism everywhere — !important so it beats any display rule. */
.hidden { display: none !important; }

.sr-only {
  position: absolute; width: 1px; height: 1px; padding: 0; margin: -1px;
  overflow: hidden; clip: rect(0 0 0 0); white-space: nowrap; border: 0;
}

/* One grouped selector for every tappable class. Extend the list with each new one. */
.cls-tab, .q-btn, .pill, .hdr-icon-btn, .class-action-btn, .batch-btn {
  touch-action: manipulation; user-select: none; -webkit-user-select: none;
}

And the head, which is as much of the design as the CSS is:

<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">

<!-- Emoji favicon: no file, no request, no 404 in the console. -->
<link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg'
  viewBox='0 0 100 100'><text y='.9em' font-size='90'>📋</text></svg>">

Then lift the header, the panel frame, the modal system and the button classes from this page's source. Keep the class names — that is what makes a fix in one app portable to the next.

12 · Voice

Friendly-utilitarian, and written for a teacher between classes.

Sentence case everywhere, except the uppercase 10px micro section labels. Not Title Case On Buttons — it reads as marketing, and this is a tool.

Emoji are functional signposts — 📋 ⚠ 🚫 ✓ ↩ — used sparingly in chrome and banners, never decorating body text.

Errors say what happened and what to do next, in that order, in one sentence each. "The bridge did not respond within 15 seconds. Check your connection and try again." Not "An error occurred." A message that does not end in an action the reader can take is a message that makes them find you instead.

Never use a softer word than the truth. A save that failed says failed. The cost of an accurate scary word is a moment of alarm; the cost of a reassuring inaccurate one is a term of work the user thought was safe.

Modal specimen

480px wide, 14px radius, capped at 95vw, entering with the 0.18s srIn animation. The gradient header is the two-stop variant, not the three-stop one the page header uses.

The overlay scrolls and the panel is centred with margin: auto rather than by align-items alone. Centring a too-tall flex child clips its top edge with no way to scroll back to it — an iPad in landscape is 704px of usable height, which any modal with a form in it will pass.

Escape closes it, so does a click on the backdrop, and either one puts focus back on the button that opened it.
