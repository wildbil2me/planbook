What WO-8.4 changes on paper

Four surfaces already print. The attendance record (WO-2.6), one student’s report (WO-3.7), the grade sheet (WO-3.9) and the calendar (WO-6.3) each have a gated @media print block. The sheets below show what those blocks produce today, redrawn at their own sizes. The new part is the band at the top of each sheet: what the sheet is, the class, the term, and the date it was printed, laid out the same way on all four.

What the band replaces. Today each surface titles itself in its own way. The record and the grade sheet print the class name, a caption, and a Printed … · Planbook line. The student report puts a date stamp under the hero. The calendar prints Planbook · September 2026, with no class, no term and no print date, so it is the only sheet that fails the first Acceptance line today. In this drawing the band takes over those jobs on all four, and each surface keeps only what is its own.

ASK — one shared #printHeader, or four heads that just match? The style guide’s idiom is one hidden #printHeader in index.html that becomes visible in print. That means one element filled from four places, and each surface’s own head hidden under its gate. The alternative is to keep each surface’s head where it is and restyle all four to this layout. Both print the same page. The first is the idiom the work order names. The second keeps the screen and the sheet as one element, which is what src/attendance-report.js argues for at its own header (“it is the same element on screen”).

ASK — landscape. A month is wider than it is tall, and portrait Letter gives each day about 26mm, where two chips already wrap to four lines. The drawing shows landscape. Chrome and Edge honour a named page (@page calendar { size: landscape } with page: calendar on the view), so the calendar can come out sideways while the other three sheets stay upright. Safari on the iPad ignores it, so there the teacher turns the preview herself. Landscape for the month only, or leave orientation to the print dialog?

ASK — the band’s class and term lines on a calendar. The calendar is not a class screen. Its filter can show every class, one class, or several, and terms belong to classes, so five classes can have five different Quarter 1s. The drawing prints the filter as words (“All five classes”) and prints the term only when every showing class has the same one. With a single class, it would read English III — Period 2 in the class slot, like the other three sheets. Is that the rule?

Presentation mode, on paper

Every sheet above is the same with presentation mode on and off, which is the fourth deliverable. None of the four surfaces shows a support field. The record and the grade sheet say in their own footers that nothing from a student’s support details is on them, the student report has no import path to supports, and the calendar’s one support-derived chip is removed twice. That is why no second copy of any sheet is drawn in the other mode: it would be identical.

ASK — the belt for everything else. What the four gated blocks do not cover is a plain Ctrl+P from a screen that is not a print surface, such as the roster, where the .support-dot is. That prints the screen as it stands, with presentation mode deciding what is on it. src/assignments.css and src/calendar-view.css already each carry an ungated, hide-only print rule for their own sensitive element. The deliverable reads as one more of the same in src/shell.css: an ungated @media print that hides every support indicator in the app, whatever the mode. It is not drawn because it has no look, only an absence. Is one belt in the shell the shape, or should each screen with a support element keep its own?

ASK — body[data-modal-print]. The second deliverable asks for the style guide’s single-modal gate. The app has four per-surface gates in src/print-gate.js instead, and the header of that file explains why one shared attribute would print the wrong surface. That deliverable may already be met in a better form, and closing it needs your ruling rather than new code. Nothing here to draw.
