Nothing is filed under Participation yet, so its weight redistributes across the other four categories rather than counting as a zero. Every grade in this class is already correct — it is being worked out as though Participation did not exist.

The screen switcher: three tabs, and a class always opens on Attendance. (Owner, 2026-08-09.) This strip was drawn as one candidate to argue with and WO-3.3 now builds it. Two things changed in the arguing. It carried a fourth tab, A student, set apart by a gap — but you cannot enter that screen without first choosing a student, so as a tab it is either dead on a freshly-opened class or it picks someone for you. Per-student detail is reached by tapping a name instead, and the strip shows that name as a breadcrumb only while you are in it (drawn on student.html). And a class opens on Attendance every time, never on the screen it was left on: the critical path is marking at the door while the class walks in.
A view with modal editors, not a modal. The list is a surface a teacher scans in the week before grades are due; creating one assignment is a task she finishes and dismisses. Same split as the roster. The editor is drawn below.
The "Entered" bar is why this screen gets opened. The question is never "what did I assign", it is "what have I not finished putting in" — and a part-filled amber bar answers that without arithmetic. The half-entered state takes the caution wash for the same reason src/home.css and src/attendance.css both do: partly-done must not read as done.
The empty category says its own consequence. An empty group with nothing under it is how a teacher concludes the app lost her work; the sentence that its weight redistributes is the data model's rule stated where it bites. Note it appears even at 0% weight, where the redistribution is a no-op — worth deciding whether that sentence should be suppressed there.
Open question — five buttons per row is the class manager's problem all over again. Nine assignments × five controls is 45 targets on one screen, and on a phone this row wraps to two lines each. The alternatives: a single ⋯ per row opening a small menu (fewer targets, one more tap for the common case), or dropping Duplicate to the menu and keeping Edit and the arrows inline. Drawn wide on purpose so the crowding is visible rather than argued about.
