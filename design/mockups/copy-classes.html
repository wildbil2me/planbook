Nothing in P5 · English III is called “Essays”, so this copy is not filed under a category yet. Pick one above, or file it later from its own row — a category id belongs to the class it was made in and is never carried across.

The assigned date comes across as it is. Each due date starts on this assignment’s and can be changed in its own row — nothing re-dates a copy to today. Nothing about a copy is settled by making it: it is an ordinary assignment in its class the moment it exists.

Every class is on screen twice: once as a pill and once as a card. Each card is three blocks deep, because three fields and a Clear don’t fit across 480px. Every field also repeats its own label. Under a thumb the term and category stack too, which makes each card about 280px, and three classes are more than a landscape iPad’s 704px of usable height. And the card asks for a term, which the due date already decides, but can’t move the assigned date, which a section a day behind needs.

The same markup as frame A, folded by the list’s own width. Each ticked class takes two rows: the tick and name, then category, assigned and due side by side, each with a small label because the column heads are gone. An unticked class is one row. On a laptop this frame shows the fine-pointer sizes. On the iPad every control is 44px, about 130px per ticked class against about 280px today.

Open 2 · folding by the panel’s width. This frame folds because the list is a CSS size container (@container), which is what lets one page show both layouts. Nothing in src/ uses one yet. It needs iPadOS 16 or later. The alternative is a @media (max-width: 900px) rule, the shape the app already uses, which folds by window width and behaves the same on real devices.

Open 3 · two dates and two Clears on a portrait line. Each date cell carries a Clear beside it (WO-1.48’s button, which isn’t optional). If the iPad draws a date field wider than a third of the line, the fallback is the two dates on a row of their own under the category, which adds about 50px per class. Only a thumb on the real device can settle this.

Open 4 · the order of the list. Drawn in the class manager’s order, with the source class first only from a row’s Duplicate. Another option is to put the source course’s other sections first (P2 and P4 here), because those are almost always the ones ticked. That would be the first place this dialog sorts by anything other than the class manager’s order.

Open 5 · a “tick every section of this course” shortcut. Not drawn. With five classes it saves two taps. It could sit in the list head beside “Class” if it turns out to be wanted.

Open 6 · a due date no term holds. Blank (a due date is never required), in the gap between two terms, or in a class whose term dates aren’t typed in. Proposed: a blank due date falls back to the term holding the assigned date. A date outside every term blocks that line the way P3 does, and the line says to change the date, because a term dropdown would be the one place the app files work against its own dates.

Open 7 · moving the assigned date. Drawn so that it moves only the assigned date. For a section a day behind, both dates usually move, which takes two edits. The other option is for the due date to follow by the same number of days, but nothing else in the app changes one date because another one moved.
