What these checks cannot see

  • A clean report means “no unexcused occurrence”, not “the document is right.” 38 checks are 38 questions somebody thought to ask. A wrong score that is well-formed is invisible here and always will be.
  • There is no provenance in the document. Nothing records which build, screen or gesture wrote a cell, so every “how it got there” above is a reading of the shape, offered as a suspect. Treat it the way plans/known-bugs.md treats one: write the reproduction, not the diagnosis.
  • It cannot tell a deliberate empty from a lost value. An empty note, a cleared date and a { } cell all read as absence — which is exactly the ambiguity WO-1.48 exists to remove at the input.
  • It reads the document as stored and applies no migration. A file below schema 3 is reported as-is, because an anomaly you are chasing may be the thing the migration would repair on the way in — and then you would be reading the repair.
  • It does not know what the screen was showing. The Counts tab recomputes both readings from the same document; it is evidence about the data, not about the render.
